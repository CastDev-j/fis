## Calidad
#### ¿Qué es calidad?

La totalidad de características de un producto o servicio que se refieren a su habilidad para satisfacer necesidades establecidas o implicadas. No es algo absoluto: cada persona la juzga diferente según su percepción, educación, experiencia y estado de ánimo.

![[Pasted image 20260902113606.png]]
#### Calidad Total

Conjunto de principios orientados a mejorar continuamente todos los aspectos de un producto o servicio, involucrando a todas las personas y procesos de la organización.

![[Pasted image 20260902113617.png]]

## Software
#### ¿Qué es software?

Elemento lógico (no físico) de un sistema, desarrollado a la medida para satisfacer la necesidad de un cliente o usuario. Tiene características distintas al hardware.

#### Software de calidad

Un producto de software es de calidad si cumple con los factores de calidad: hace lo que debe hacer, el cliente queda satisfecho, no tiene errores, eficientiza la labor del usuario.

## Proceso de software
#### ¿Qué es un proceso?

Serie de acciones que conducen a un final, con **orden, dependencias, roles, responsables, resultados, tiempos y herramientas de apoyo**. Pueden ser predefinidos o personalizados.

![[Pasted image 20260902120237.png]]
#### Proceso de desarrollo de software

Conjunto de personas, estructuras de organización, reglas, políticas, actividades, procedimientos, componentes de software, metodologías y herramientas utilizados para definir, desarrollar y ofrecer un producto de software.

![[Pasted image 20260902120344.png]]

**¿Dónde quedan entonces todos los elementos de los que hablamos antes?**

- Orden, Dependencias, Roles, Responsables, Resultados, tiempos de ejecución, Herramientas de apoyo
#### Relación calidad-proceso y calidad de software

**Calidad en el proceso ≠ Calidad del software.** El resultado del software depende del proceso: si se tiene un buen proceso de desarrollo, se obtendrá un software de calidad.

## Aplicar calidad al proceso de desarrollo

#### 1. Planear y organizar

- Fijar objetivos alcanzables y medibles.
- Organizar el equipo y determinar roles.
- Dividir el proyecto en fracciones, trabajando en equipo en cada una.
- Asignar recursos necesarios y administrar el tiempo (recurso que no se controla, se administra).
- Prevenir riesgos.

#### 2. Capacitarse

Un miembro capacitado se compromete más fácilmente porque entiende la terminología, se comunica mejor, comprende la metodología y aporta mejores ideas de solución.

#### 3. Ejecutar según lo planeado

- Definir un modo estándar de trabajo: modelo de desarrollo, herramientas, documentos y nomenclatura.
- Verificar, revisar, probar, validar y **registrar** todo.
- Participar involucrándose activamente.

#### 4. Mantener buena comunicación

Comunicar todo: dudas, hallazgos, cambios, problemas, éxitos, correcciones y oportunidades de mejora. Aprovechar redes sociales, correo y celular.

#### 5. Llevar registro

- Tiempos efectivos, errores encontrados, bitácora de actividades y minutas de acuerdos.
- Siempre preguntarse el **por qué** de los resultados.

#### 6. Cierre de proyecto

- Registrar experiencias positivas y negativas, aprendiendo de ambas.
- Realizar gráficas comparativas.
- Tener reunión de cierre para replantear estrategias.
- Analizar resultados y proponer mejoras basadas en datos.
- Practicar con múltiples proyectos.

## Ventajas de aplicar calidad

- El cliente obtiene un producto que refleja los requerimientos solicitados.
- Se obtienen datos de referencia para costear proyectos.
- Como equipo: mejor control del proceso, experiencia, estrategias reformuladas y mejor comunicación.

#### Costo de implantar la calidad

Sí tiene costo: capacitación, más recursos y correcciones. Pero **baja si el equipo es proactivo** en las primeras etapas en lugar de reactivo. Los beneficios pueden ser tangibles o intangibles.

#### El verdadero "secreto"

Estar convencido de que se quiere hacer bien.
